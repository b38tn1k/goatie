# manbun-audit a11y reference — current as of mid-2026

Audit target: **WCAG 2.2 AA**. It is backward-compatible with every
legal baseline in force (see the table), the UK already monitors
against it, and EN 301 549 v4 (folding in 2.2) publishes ~2026.
One removal: **4.1.1 Parsing no longer exists** — never report
duplicate-id/markup-validity as a WCAG failure.

## The WCAG 2.2 checks older checklists miss

Run these on every walked screen; each has a mechanical test:

| SC (level) | Test |
|---|---|
| 2.4.11 Focus Not Obscured (AA) | Tab through; assert the focused element's rect is not fully covered by sticky headers/footers/banners (`getBoundingClientRect` vs `elementsFromPoint`). Cookie banners are the usual offender. |
| 2.5.7 Dragging (AA) | Anything draggable (sortables, sliders, kanban) needs a single-pointer non-drag alternative — buttons, click-to-place. Drag-only = failure. |
| 2.5.8 Target Size (AA) | Every interactive target ≥ 24×24 CSS px (hit area: padding counts, margin doesn't), unless spaced (24px circle test), inline in a sentence, browser-default, or duplicated by a conforming control. Report three bands: <24 fail-candidate · 24–43 platform warning (Apple 44pt, Material 48dp) · ≥44 pass. |
| 3.2.6 Consistent Help (A) | Help/contact/chat mechanisms appear in the same relative place on every screen. |
| 3.3.7 Redundant Entry (A) | Multi-step flows never ask the user to re-type what they already entered — autofill it or offer it. |
| 3.3.8 Accessible Auth (AA) | Login: no cognitive test without an alternative. Flag paste-blocking on password/OTP fields, `autocomplete` off on credentials, CAPTCHA with no alternative, password-manager hostility. |

(2.4.12/2.4.13 and 3.3.9 are the AAA versions — note, don't gate.)

## Contrast policy — dual band

**WCAG 2.x ratio is the conformance floor** (4.5:1 text, 3:1 large
text, 3:1 non-text) — it gates. **APCA is advisory only**: it is not
normative anywhere (pulled from the WCAG 3 draft in 2023; WCAG 3
remains an exploratory draft years from Rec). Use it as the second
opinion where WCAG 2 math is known to mislead: dark mode (2.x
*overstates* contrast for dark pairs — a 4.5:1 pass near black can be
unreadable) and thin/small fonts (the 18pt cutoff is crude).
Report: WCAG2-fail = violation regardless; WCAG2-pass + APCA-poor =
warning, especially on dark themes.

## Modes — the full 2026 render set

Light · dark (full contrast pass in EACH) · CVD sims/grayscale ·
**forced-colors: active** (Windows Contrast Themes: does content
survive background-stripping, do transparent focus outlines appear,
do color-only states die?) · **prefers-contrast: more** (do the styles
actually increase contrast?) · **prefers-reduced-motion: reduce**
(animations, autoplaying video/Lottie stop) · **reflow at 320 CSS px**
wide (SC 1.4.10: no 2-D scrolling, nothing lost) · **200% zoom**
(1.4.4) · **text-spacing override** (1.4.12: inject the standard
spacing stylesheet, assert nothing clips or overlaps — snippet in
`toolkit.md`).

## Legal landscape (verified mid-2026 — cite dates, don't trust older checklists)

| Regime | Standard | Status |
|---|---|---|
| EU EAA (private-sector services incl. mobile apps) | EN 301 549 → WCAG 2.1 AA today, 2.2 AA lands with v4 (~2026) | In force since 28 Jun 2025; legacy backstop 2030; microenterprise exemption; also requires an accessibility statement in T&Cs — check it exists |
| US ADA Title II (state/local gov) | WCAG 2.1 AA | Deadlines EXTENDED Apr 2026: ≥50k pop → 26 Apr 2027, smaller → 2028. "April 2026" in a checklist = stale |
| US HHS 504 (health orgs) | WCAG 2.1 AA | Also extended: May 2027 / 2028 |
| US Section 508 (federal) | WCAG 2.0 AA (2017 refresh) | Unchanged |
| UK public sector | **WCAG 2.2 AA** | Monitored since Oct 2024 |
| Ontario AODA | WCAG 2.0 AA | Reporting year: 2026 |

## Also check

- **Overlay widgets** (accessiBe-class scripts): detect and warn — they
  don't remediate the underlying failures, and the FTC fined the claim
  itself ($1M order, 2025). An overlay is a finding, not a mitigation.
- Mobile apps are in scope for EAA / Title II / 504 — the audit's
  "other cameras" path is a compliance path, not a nice-to-have.
